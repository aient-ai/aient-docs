# Aient CLI

The `aient` command runs local development work in isolated remote sandboxes. The current release is available as a static binary for macOS and Linux on Intel and Arm.

## Install and verify

Download the current release from the [Aient CLI release repository](https://github.com/aient-ai/aient-cli/releases/latest). Follow the repository's [installation and verification guide](https://github.com/aient-ai/aient-cli#install-on-macos-or-linux) before placing the binary on your `PATH`.

Each release includes static archives, SHA-256 checksums, SPDX SBOMs, Sigstore verification bundles, and SLSA provenance. GitHub-generated source archives are documentation only; they are not verified Aient CLI release artifacts.

```sh
aient version
aient auth login --print-url
aient auth status
```

## Customer Agent conversations

From a configured project, select the refresh-backed customer OAuth profile explicitly with `aient --profile NAME agent ...`. Ambient project access is sandbox-scoped and intentionally does not grant Agent conversation authority.

Find a reconnectable Agent Thread or attach to one:

```sh
aient agent list [--search QUERY] [--status all|active|closed] [--include-archived] [--limit 1-100] [--cursor CURSOR] [--json]
aient agent status THREAD [--json]
aient agent events THREAD [--follow] [--json]
aient agent message THREAD MESSAGE... [--operation-id UUID] [--immediate] [--capability computer-use] [--json]
aient agent respond THREAD INTERACTION ANSWER... [--operation-id UUID] [--json]
aient agent cancel THREAD [--operation-id UUID] [--json]
aient agent chat THREAD
aient agent execution status EXECUTION [--json]
aient agent execution attach EXECUTION
aient agent execution wait EXECUTION [--json]
aient agent execution cancel EXECUTION [--json]
```

`agent list` accepts an exact Thread ID or title query plus explicit status, archive, page-size, and cursor filters. Its human continuation command preserves the active filters; `--json` emits one versioned page. List, status, and events require `aient.agent.read`; messages, answers, explicit cancellation, and chat mutations require `aient.agent.write`. `status --json` emits one deterministic document. `events --follow --json` emits JSONL and can resume after a durable sequence. Stable Thread, task, message, interaction, operation, sandbox, and execution identifiers preserve the reconnect path after terminal or network loss.

`--immediate` requires one explicit stable operation UUID; an ordinary message may omit it and let the CLI generate one. Reuse an explicit UUID only for an exact retry. Exact text and delivery mode return `duplicate`; changed text or mode returns `operation_conflict`. Immediate delivery never cancels or replaces the active task or changes its tool scope. The receipt reports `steered`, `started`, `queued`, or `duplicate`; incompatible active-task origin or attachment plans fail with `cooperative_steering_scope_mismatch`.

`--capability computer-use` selects compact browser and Linux desktop accessibility observations, native input and optional screenshots for the task created by this message. It queues behind active work, rejects `--immediate`, and leaves later ordinary messages using Agent defaults. The runtime manages setup, recording and cleanup; existing permissions and sandbox admission still apply. An exact retry must preserve the message, operation ID and capability selection.

Inside `agent chat`, enter `! COMMAND` to run a supervised shell command in the environment and sandbox frozen from the latest rendered Agent status. The CLI shows the target and preallocated execution UUID before output, passes no workstation process environment or local repository inference, and sends no Agent message. Reconnect by passing the exact `EXECUTION` identifier to the execution commands above. Ctrl-C in ordinary chat detaches without cancelling Agent work; Ctrl-C in the active remote-command view explicitly requests cancellation of that exact execution. This release requires an existing `THREAD`; it does not start a new Agent Thread.

The standard `aient-agent` catalog uses the V3 workspace writer. The retained `aient-pr-e2e` catalog remains the V2 rollback control. The server keeps the closed V2 and V3 readers and negotiates capabilities per template; the CLI does not infer one global workspace layout version.

### Sync selected files into an Agent checkout

```sh
aient --profile "$PROFILE" agent worktree sync THREAD /absolute/local/repository \
  --repository OWNER/REPO --path apps/frontend/src/App.tsx --json
```

Repeat `--path` for 1–128 existing regular files, each at most 64 KiB. This one-shot command targets the Agent’s current primary checkout on a compatible runtime; unsupported runtimes and another repository are rejected. Selection follows Git/extras policy; `--include` explicitly allows ignored source. Git control files, `.aient`, active credentials, symlinks and submodules are rejected.

Each write atomically replaces an existing single-link regular destination, preserving its mode; remote parents must already exist. Whole-file updates use last completed write wins, while the model’s line-hash edit checks remain in force. Agent ownership, incarnation and lease remain unchanged; Git metadata is not synchronized.

JSON separates confirmed `writes` from `notification`. Exact path, byte count, SHA-256 acknowledgement and terminal exit zero confirm each write. After the batch succeeds, a cooperative path-change notice asks the Agent to reread. Delivery does not prove a model read or application reload. Failed or ambiguous writes send no success notice; earlier confirmed writes remain applied. If notification alone fails, retry only `agent message` with the returned exact text, operation ID and `--immediate`.

From a configured Aient Git project on macOS, login establishes bounded project access by default. The refresh credential stays in Keychain while launchd rotates only a short-lived repository-private envelope for up to 90 days. Login returns only after manager-owned renewal is verified. No foreground terminal or PID owns renewal. New installations persist the directory birth time so an APFS device-number change across a remount does not invalidate the same protected project. A legacy installation whose APFS device already changed still fails closed once; if the host profile is healthy, `aient --profile NAME auth export --store-in-project` replaces it without another login. Linux managed renewal remains preview pending a real systemd-user and D-Bus Secret Service renewal, restart, and logout canary. Use `--project-access=none` for host-only login, managed-project opt-out, or to avoid the Linux preview.

## Quick start

From a local Git checkout:

```sh
aient sandbox run --environment development --size medium -- pnpm test
```

With `--environment`, the CLI synchronizes the current workspace by default. It shows the organisation, resolved environment, inferred or selected repository, and brokered GitHub capabilities before creating the sandbox.
Use `--size small|medium|large` to request a product-owned compute class, or omit it to use the environment default. The server owns the underlying template and resource envelope.
Every customer-development create advertises `developmentSizeBindingVersion: v2`. A compatible product response binds exact `aientSizeBinding=v2`, `aientSizeClass`, `aientSizeSource=requested|environment-default`, and `aientSizeEnvelope=v1|v2` selectors into the signed request target. Partial, duplicated, unknown, crossed, or mismatched bindings fail before the control-plane request. Legacy explicit V1 and an old server's unbound environment default remain supported during rollout. This size-binding reader does not choose the workspace writer; the standard `aient-agent` catalog uses V3 independently.

```text
Organisation: Example Engineering
Environment:  development
Repository:   example/widget (inferred from origin)
GitHub access: branch push, pull requests
```

The local checkout is the workspace source. A configured Git remote is only a repository selector. The Aient service verifies membership, environment policy, repository ownership, and the active GitHub App installation before granting any provider operation.

<Note>
  An organisation administrator must enable customer CLI workspaces for the selected environment. If it is disabled, the command fails before sandbox creation with `HTTP 403: development environment is not enabled for CLI workloads`.
</Note>

## Choose a workflow

Use `sandbox run` for a disposable command:

```sh
aient sandbox run --environment development --size medium -- go test ./...
```

Use `--keep` when you want to retain the created sandbox:

```sh
aient sandbox run --environment development --keep -- pnpm install
aient sandbox list --environment development
```

Use detached ownership when the command must survive the initiating client. A composed run must also be retained:

```sh
aient sandbox run --environment development --name background-tests --detach --keep -- pnpm test
aient sandbox execution status background-tests EXECUTION_ID --environment development
aient sandbox execution attach background-tests EXECUTION_ID --environment development
aient sandbox execution wait background-tests EXECUTION_ID --environment development
```

Every ordinary CLI process starts one fresh execution. Recovery inside that process reuses the exact execution ID and never redispatches the command; running the same command in another process starts another execution. Before the admission request, `sandbox run --json` and `sandbox exec --json` emit `execution_started` with `executionId` and `outputCursor` after publishing the cursor-0 local pointer. This identifies the admission attempt for reconnect; it does not prove that the server admitted or started the command. The validated server admission frame remains authoritative.
`sandbox execution attach SANDBOX EXECUTION --after-cursor CURSOR` replays supervisor-retained output after the caller's last accepted cursor, then follows live output. The cursor advances only after a complete frame is presented, so reconnect may repeat one frame but never silently skips output. While a client is connected, the command runs at the client's pace. If a reconnect resumes after output the server no longer retains, stdout keeps only the bytes received before the gap, the retained tail goes to stderr between an `aient: output incomplete: bytes FROM-TO lost; ...` header that names the command's own exit status and an `aient: output incomplete: end of retained tail` line, and the exit status is 74. `--json` reports the gap as an `execution_output_gap` event and also exits 74.
`--timing-json` emits one content-free JSON line on stderr without changing command output or exit status. It records process-relative preflight, create-ready, proven workspace activation, first output, truthful terminal status, downloads, and confirmed cleanup or retention. Same-execution recovery never dispatches a replacement command, and a timing-writer failure cannot mask the command result.
Automatic disposable cleanup performs exactly one DELETE with the full configured `--timeout`, then a fresh equally bounded GET-only absence check. Ambiguous deletion is not retried. A failed lease restore keeps the primary error authoritative and reports `retained=true` with `cleanupConfirmed=false`; genuine lease-refresh failures still warn and retry while an active heartbeat continues.

A foreground CLI reconnects the same execution during a bounded grace. If it must leave a potentially live execution, it retains the sandbox and prints the exact attach command. Cross-process reattachment is explicit; an ordinary new run always starts a fresh execution.

Use a named retained sandbox when you want follow-up lifecycle reads and supervised execution:

```sh
aient sandbox run --environment development --repository owner/repository \
  --size medium \
  --name laptop-offload --keep -- true
aient sandbox status laptop-offload \
  --environment development --repository owner/repository
aient --timeout 15m sandbox exec laptop-offload \
  --environment development --repository owner/repository \
  --workdir /workspace/repo -- go test ./...
# After your next local edit, synchronize and execute in the same sandbox:
aient sandbox exec laptop-offload --workspace . \
  --environment development --repository owner/repository \
  -- go test ./...
aient sandbox logs laptop-offload \
  --environment development --repository owner/repository
aient sandbox delete laptop-offload \
  --environment development --repository owner/repository
```

Environment/repository-bound retained calls must repeat both selectors; repository-independent calls repeat only `--environment`. Without the matching selectors, the owner-only client deliberately cannot see the bound sandbox.

`exec --workspace PATH` accepts ordinary sync source flags and runs in the synchronized directory unless `--workdir` is explicit. A failed sync never starts the command; rerun it to sync the worktree as it is now. The sandbox keeps its existing owner and retention policy; sync may renew its lease. This command neither creates nor releases it. `--detach` waits for sync and execution acceptance. For this combined command, `--timing-json` reports synchronization only, not command execution or output latency.

`sandbox run` and `sandbox exec --workspace` also accept `--workspace-commit` with a full Git commit ID. The selected committed tree and its selected submodule Gitlinks sync without staged, unstaged, or untracked source edits. Exact-commit mode requires the default remote directory and cannot combine with extra-file selections, resets, or automatic node_modules preservation. If private HTTPS submodule acquisition needs a global credential helper or URL rewrite, initialize the submodule with your normal Git setup or configure an SSH submodule URL override.

To select ignored and untracked non-Git paths broadly, omit regular AppleDouble sidecars, and subtract explicit exclusions:

```sh
aient sandbox run --environment development \
  --exclude '**/node_modules/**' \
  --exclude '.local/**' \
  --exclude '**/.env*' \
  -- go test ./...
```

Exclude-only selection never replaces Git-tracked content or includes `.git` metadata. Regular macOS AppleDouble `._*` files are omitted from broad non-Git selection before archive, manifest, byte-count, or digest construction; the local source remains unchanged. There are no implicit cache or secret exclusions, so review the selected scope and explicitly exclude `.env` files, credentials, tokens, private keys, and other secret-bearing non-Git paths.

To replace an exact generated remote directory without changing its local contents:

```sh
aient sandbox run --environment development \
  --reset-remote-dir packages/otel/dist \
  -- pnpm install
```

`--reset-remote-dir` is repeatable explicit authority. It publishes an ordinary empty candidate-owned directory through atomic activation so build cleanup can remove or recreate it. On legacy servers, other ignored remote state keeps its existing preservation behavior. When explicit repository path ownership is advertised, unselected non-Git paths are absent unless named by `--preserve-remote-dir`. Reset paths must be exact repository-relative non-Git directories and cannot be combined with `--exclude`.

In that negotiated mode, unselected generated, dependency, and cache directories are absent from a new candidate instead of becoming inferred preservation mount roots. Package tooling can remove and recreate them normally.

To retain an exact ordinary remote directory across synchronization:

```sh
aient sandbox sync retained-sandbox . \
  --environment development --repository owner/repository \
  --preserve-remote-dir .cache/tool
```

`--preserve-remote-dir` is repeatable explicit authority. Preservation roots must be exact repository-relative non-Git directories and cannot overlap Git content, selected uploads, reset paths, symlinks, files, or one another. A server without explicit path-ownership support rejects preservation instead of silently changing its meaning.

`--preserve-node-modules` adds every pnpm `node_modules` directory that already exists in the sandbox: the root and each package listed in `pnpm-workspace.yaml`, outside submodules. Installed dependencies then survive a repeated sync, and an unchanged workspace stays a no-op.

For a deliberately incomplete parent-only checkout when submodules are initialized locally:

```sh
aient sandbox run --environment development \
  --submodules=gitlinks \
  -- go test ./...
```

`--submodules=gitlinks` recursively verifies every initialized child is clean, untracked-free, and checked out at the exact parent-index object before any remote request. It omits child bytes and binds the complete sorted parent-index Gitlink set into manifest-backed activation. This is an incomplete Gitlink-only workspace, not recursive submodule transfer; commands that need child files must initialize them separately.

To transfer only exact nested repositories consumed by the remote command:

```sh
aient sandbox run --environment development \
  --submodules=selected --submodule apps/aient-docs \
  -- pnpm --filter aient-app build
```

Selected children must be initialized, clean, complete-history repositories at their exact parent-index Gitlink OIDs. Repeat `--submodule` for every selected ancestor; selection never expands recursively. Initialized but unselected children contribute no bytes and remain empty Gitlink boundaries remotely. Selected submodules may be combined with declared parent-repository extras; the server verifies every declared path and atomic exchange before activation. Capability preflight recognizes the exact old helper generation mounted by an already-running sandbox. A reader without exact selected-submodule support rejects the operation rather than weakening the policy.

Default snapshots keep raw uninitialized Gitlink index paths exact without applying explicit-manifest UTF-8, backslash, or entry-count limits. Those snapshots emit no Gitlink manifest. Explicit `--submodules=gitlinks` remains fail-closed and applies the portability rules plus the 512-entry bound before any remote request.

## Experimental selected-file live sync

Select existing local regular source files
in an already running sandbox, publish them once, then watch ordinary local saves.
Pass the actual remote worktree explicitly:

```sh
aient sandbox sync SANDBOX /absolute/local/repository \
  --environment development --repository owner/repository \
  --live-stream --remote-dir /workspace/repo/actual-worktree \
  --live-path apps/aient-app/src/app/example/page.tsx
```

Repeat `--live-path` for 1–128 exact repository-relative files, each at most 32 MiB.
The initial upload overwrites those selected files: choose files whose overwrite
is intended. The ordinary tracked Git and non-Git include/exclude policy applies;
Git control paths, credentials, symlink sources and submodules are rejected.
Parent directory watches support ordinary editor atomic saves; identical captured
content is skipped. The sandbox keeps running when the watcher ends.

`--live-stream` requires a compatible attested native V3 workspace, existing
remote parent directories and normal customer shell permission. It sends captured
bytes over one authenticated terminal WebSocket. Each file replaces atomically;
the exact sequence, byte count and SHA-256 acknowledgement proves individual file
delivery. Setup and helper READY are measured separately from per-file delivery.
The session holds a shared workspace fence, blocking ordinary full sync and
exclusive files API writes. Ctrl-C requests helper STOP and waits for terminal
command completion. Missing proof prints `termination UNVERIFIED`: the helper and
fence may remain active and keep blocking those writes. The reported session/PID
is diagnostic metadata, not authority to kill a process. Restarting a watcher
does not recover an unverified session and overwrites the selected files again.

Use the separate experimental `--live` mode instead of `--live-stream` to upload
selected files through the files API. It requires an attested existing workspace
and normal files permission, and reads the workspace binding for each save batch.
Its diagnostics distinguish binding reads and upload duration. The files transport
remains the default. A long-running app on a compatible runtime holds a shared workspace fence,
which can block those exclusive binding reads and uploads.

For a compatible customer workspace bound to its original allocation, opt into
finite supervised execution for each selected file:

```sh
aient sandbox sync SANDBOX /absolute/local/repository \
  --live --live-transport exec --remote-dir /workspace/repo/actual-worktree \
  --live-path src/example.ts
```

Start this watcher before starting a long-running app: the one-time capability
bootstrap still requires an exclusive fence. After bootstrap, each initial write
and changed save uses normal customer exec authorization and a shared fence,
compatible with ordinary app execution. There is no per-save capability read or
files API upload. Each selected file must already exist remotely as a single-link
regular file with existing ordinary parent directories, and each captured source
is limited to 64 KiB. Replacement preserves the remote mode. Unsupported targets and
operator profiles reject this transport; there is no automatic fallback.

Only an exact path, byte-count and SHA-256 ACK together with terminal exit 0
confirms delivery. Missing proof reports `write UNCONFIRMED`, stops the watcher
without retry, and means remote bytes may have changed; reconcile selected files
before restarting. Each command is bounded to 30 seconds, and sandbox hard expiry
still applies. Diagnostics measure save detection through confirmed ACK;
application visibility must be measured separately.

Both live modes require explicit `--remote-dir` and `--live-path`; choose only one
mode. `--live-transport` requires `--live`.

Both modes perform no snapshot activation, application restart or Git metadata
synchronization. Deletions, renames, new unselected files, mode changes, concurrent
edit protection, submodules, overflow/reconnect recovery and multi-file consistency
are unsupported. Errors stop the watcher. Delivery does not prove application
readiness or browser HMR, and there is no universal subsecond latency guarantee.
Existing finite sandbox leases and hard expiry apply.

## Workspace operations

Workspace operations live in `~/.aient/workspace-operations` only while the command that started them runs. When a `sync`, `run` or `exec --workspace` operation ends, whether it activated, failed or was cancelled, nothing of it is kept there. If a sync is interrupted, rerun the command: it syncs the worktree as it is now; nothing is resumed. `sandbox run` deletes its sandbox after a failed sync unless `--keep` is given. Removing the local record can itself time out or fail, for example while another process holds the store lock for more than 10 seconds. That never changes the result: the CLI prints one line saying the record could not be removed yet, a synced workspace stays synced, `sandbox run` still runs its command, and the next sync or `sandbox workspace list` removes the record. Otherwise only a killed CLI leaves a directory behind, and the next sync or `sandbox workspace list` removes it if this version created it. Records that older aient CLIs created are kept, because those releases took no lock that shows whether they are still in use; delete one by hand once no older CLI is running. `list` shows the store without authentication or network access; `status` and `discard` reconcile the server side of an operation that is still recorded:

```sh
aient sandbox workspace list [--json]
aient sandbox workspace status OPERATION
aient sandbox workspace discard OPERATION
```

`aient sandbox create --env KEY=VALUE` (repeatable) sets an environment variable for the sandbox's processes. The values are stored with the sandbox and are not secret; use environment secrets for credentials. A sandbox whose start-up keeps failing ends `failed`, and the create prints its reason.

When one selected submodule cannot use the Git cache (a network, DNS or sign-in discovery failure, an unavailable server, or a repository with no cache authority), that submodule uploads directly on its own while the root keeps its cached delta, instead of the whole workspace uploading. A cancellation, a changed capture, or an authoritative refusal of that repository (HTTP 401, 403, 409, or 404 other than an unregistered repository) still stops the cache operation. The root cache lookup and root seed start retry network failures up to three attempts.

## Pull request reviews

`aient review OWNER/REPO#NUMBER` asks aient-cto[bot] for an independent review of a pull request's current head, posted as a GitHub review: an approval, a change request with inline comments, or a comment without a verdict. While it waits it prints progress (`queued`, then `reviewing`), then the outcome and the review's link (`--no-wait` returns once the review is requested, `--json` prints the review). A repeat for the same head returns the review already given, at once. It needs the repository connected to your organisation and the Aient CTO GitHub App installed on it, and uses the `aient.agent.write` scope (plus `aient.agent.read` to wait). When no review can be given, it says what to do and exits non-zero.

## Native Claude Code and Codex sessions

Continue a stopped local native session in an existing Aient sandbox, then bring
its saved conversation and selected Git worktrees back to a fresh local destination.
Claude handoffs include the selected parent's saved subagents and checkpointed
Team teammates. Native files remain the conversation authority.

In `teleport <sandbox> [<workspace>]`, `<sandbox>` is a required sandbox name
and `[<workspace>]` is an optional local checkout path. The examples use
`native-work` as the sandbox name. Before exiting Claude, run `/status` in the
parent and copy its full **Session ID** UUID, or name it with `/rename fix-login`.
Pass the UUID or a unique saved name in this checkout with `--session`; a name
must match exactly and uniquely. The resolved UUID remains the handoff identity.
Omit `--session` to select the latest saved parent in that checkout.

For a Claude Team, save its checkpoint while the parent and teammates are still
live. Obtain each selected split teammate's actual Session ID from `/status`
and repeat `--teammate-session NAME=UUID` for every selected split member:

```sh
aient --profile NAME sandbox session checkpoint /absolute/local/worktree \
  --session "fix-login" \
  --teammate-session "worker-one=<worker-session-uuid>"
```

The checkpoint prints its private path and exact teleport command, including
`--team-checkpoint`. In-process teammates come from the parent's saved sidecars;
ordinary saved subagents do not need a Team checkpoint. Exit every local
teammate and the parent before running the printed Team teleport command.
The Team adapter is qualified for Claude Code 2.1.312 remotely and 2.1.314
locally. A 2.1.318 source journey has also been exercised through these
remote/local versions; this does not qualify every other source version or
terminal-backend combination. It restores selected saved members and tracks new
teammates Claude creates inside the mapped workspace. New saved histories, unstarted reservations
and their associated worktrees return under execution/checkpoint provenance
checks; roots outside the mapped namespaces are rejected.

Use an authenticated Aient profile and a sandbox you own. Install the pinned
native tools, then teleport the stopped selected session (for Teams, use the
checkpoint's printed command):

```sh
aient --profile NAME sandbox session setup native-work --agent claude
aient --profile NAME sandbox session teleport native-work /absolute/local/worktree \
  --agent claude --session "fix-login"
```

Use `--agent codex` for Codex or `setup --agent both` to install both tools.
The native agent uses your native login. `--config-dir`, `--credential-file`
and `--keychain-service` select a custom native store.

New handoffs use `/workspace/repo` as one envelope, with checkouts under `trees/`.
A single-checkout handoff uses `/workspace/repo/trees/root`. Selected sibling
checkouts preserve their relative layout beneath their common source ancestor,
so the primary checkout can have a different path under `trees/`. Use `pwd` in
the attached native session to find its mapped checkout, then run
`git worktree list` from that path. Both agents can include additional canonical
Git worktree roots with repeatable `--worktree PATH` options; every added root
must share the primary checkout's Git common directory:

```sh
aient --profile NAME sandbox session teleport native-work /absolute/local/worktree \
  --agent claude --session "fix-login" --worktree /absolute/local/other-checkout
```

For Claude, verified native-associated ordinary and Team worktrees are included
automatically. Other worktrees registered in Git are not selected merely because
they exist. Added roots use ordinary nonignored selection, exclusions, reset and
selected-submodule options. Primary-relative `--include` patterns stay limited to
the primary checkout; they do not copy matching ignored files from added roots.
For a Team, add these flags to the checkpoint's printed teleport command.

Claude's default project auto memory also travels with the saved session: its
complete `MEMORY.md` index and topic files shared by the repository's worktrees.
Returned memory stays in the isolated returned Claude config, preserving other
laptop sessions' canonical memory. `--sync` watches selected workspace files, not
config memory. This default-memory scope does not promise custom memory locations
or per-agent memory overrides.

Native conversations, including Claude's saved subagents and Team teammates,
remain behind retained sandbox executions; they are not imported as first-class Aient chats or Agent Task history. Use
`session status` to inspect the execution, and `session attach` or native tools
to inspect the conversations.

The execution budget defaults to eight hours. Choose another finite budget
with `--budget 8h`; it must fit the sandbox's remaining lifetime. In the native
terminal, press tmux's `Ctrl-B`, then `D` to detach. You can close the local
terminal and reconnect to the same running process:

```sh
aient --profile NAME sandbox session attach native-work --agent claude
aient --profile NAME sandbox session status native-work --agent claude
```

The CLI requests 24-hour sandbox retention, capped at the existing hard expiry
of 24 hours from sandbox creation. This leaves a finite recovery window after
the command ends; an older sandbox has less time remaining. Return before that
expiry: surviving execution metadata cannot recover an expired sandbox.

Reattachment never starts a replacement or resets the execution deadline.
`teleport --detach` starts without attaching. `session watch native-work`
runs a separate local observer. Add the native session UUID or execution ID as
`session attach native-work <native-id>` when more than one retained session
matches.

Add `--sync` to `teleport`, `attach` or `watch` for optional continuous
synchronization of regular source files in both directions while that local
observer is running:

```sh
aient --profile NAME sandbox session attach native-work --agent claude --sync
```

The handoff retains its source selection: tracked files stay selected, ordinary
nonignored new files are included, `--include` adds declared ignored paths,
and `--exclude` omits matching non-Git paths. Explicitly selected submodules
retain their selected namespaces. The watcher propagates new files, deletions,
renames and mode changes. Overlapping edits use timestamp-based save ordering
with guest-clock normalization; equal times choose the remote copy.
If both sides changed and one deleted the file, the edit wins because the
deletion time is unknown; a deletion with no other change still propagates.
Synchronization is per file and does not merge concurrent edits. Git metadata
and live symlink changes remain outside the watcher. Files above 32 MiB are
reported and suspended without reading their bodies; other files continue.
Full handoff and return preserve larger files within workspace transfer limits.
A sleeping laptop has no running observer to copy files.

The watcher covers only the worktrees selected at handoff. Worktrees created
later stay outside it, even if an include pattern matches their files. New
associated roots return with the full group; returning and teleporting again
selects them for the next watcher.

Exit the remote agent with `/exit` or `Ctrl-D`. For a Team, exit every remote
teammate and the parent; stopping only the parent is insufficient. Then stop
the retained execution to confirm its native writers have stopped and close
any retained tmux pane before returning:

```sh
aient --profile NAME sandbox session stop native-work --agent claude
aient --profile NAME sandbox session return native-work --agent claude --resume
```

Return creates a fresh local envelope beside the original, preserving every
associated checkout's remote Git commits, staged and unstaged changes, deletions,
nonignored new files and selected initialized child repositories.
`--output /absolute/new/envelope` names that envelope, preserving the checkout
layout under `trees/`. Resume selects the mapped primary checkout, which need
not be `trees/root`. `--resume` launches the local native agent there and resumes
the saved conversation. Omitting it completes the download and prints a resume
command. Team export needs no local Claude binary: it prints an Aient
`session return ... --resume` command, which requires qualified Claude Code
2.1.314 when you choose to resume.
Verified return inputs survive interruption; a completed return retries offline
only while its destination still matches. Later local edits and the original
checkout are preserved. After timeout or cancellation with `session stop`, use
the same return command to recover the last persisted conversation and files.
Return requires a recorded native process identity and fresh proof that it and
its process group and terminal session have no live writers. Missing proof,
a live writer or an unknown execution outcome refuses capture. Recovery does
not promise to restore an interrupted model turn or unsaved progress.

Native tools perform OAuth refresh. While attached or watching, the CLI saves
accepted native credential updates to a private host backup and propagates
them to tracked sandboxes with the same native login and Aient identity.
Reconnect catches up unavailable sandboxes. Claude updates follow increasing
credential expiry; changed Codex credentials follow arrival order. Return
carries accepted credentials into an isolated local native configuration.
Credentials travel separately from source code and conversation history.

Claude login transfers contain only `claudeAiOauth`. Each destination retains its
own MCP OAuth entries and other independent native fields. A new Claude handoff
binds the exact login to its provider account and organization; different accounts
have separate private backups and propagation targets. Changing the local login
keeps the existing sandbox sessions bound to their original account. Changed login
records require matching account proof before propagation. If that proof is
unavailable, affected credential stores remain intact while terminal access and
workspace synchronization continue. Return preserves the selected sandbox login
inside its fresh isolated configuration and preserves the canonical local login
when safe write-back cannot be established. If the canonical Claude login has
both tokens blank or missing, Aient leaves it signed out instead of restoring it
from a sandbox or backup. Same-account guest updates can still enter the private
backup; return uses the accepted login in its isolated configuration without
changing the canonical login. A saved login may still require native sign-in.

A cleared Claude login or a missing native login file no longer blocks returning
saved work. Return preserves the conversation, selected worktrees and isolated
configuration. It uses the session's existing accepted private backup when
available; otherwise it saves the work without a login and prints native sign-in
guidance. Claude's backup remains bound to the same account and organization.
This does not restore a blank canonical login or guarantee that a saved refresh
token remains usable. Malformed, partially populated and unsafe credential
stores still refuse return.

An attached or watching Aient observer maintains the selected shared login. It
may restore a managed guest whose valid JSON contains a `claudeAiOauth` object
with both access and refresh tokens absent, null or blank, using only an
unexpired login proven to belong to the same account and organization. The
guest's MCP OAuth entries and other independent native fields stay intact.
Native `/logout` does not untrack that managed login: stop all Aient observers
for the login to leave the guest signed out. Valid logins for a different
account and malformed credential stores are preserved.

Adapted AgentBox code retains its MIT notice in `LICENSE.agentbox`.

These commands require a compatible Aient sandbox terminal service. They move
saved history and files; the remote native process remains bounded by its
execution budget and the sandbox's finite lifetime.

## Environment secrets

Organisation owners and administrators can replace an encrypted environment secret after consenting to the dedicated write capability:

```sh
printf '%s' "$STRIPE_SECRET_KEY" | aient environment secrets set \
  --environment development STRIPE_SECRET_KEY --stdin
```

The command never returns the secret value. Server-managed environment secrets are separate from local files selected for workspace synchronization.

## Runtime service mappings

Inspect discovered runtime services and repository paths, or classify one service explicitly:

```sh
aient services list
aient services paths owner/repository
aient services classify web --repository owner/repository --path apps/web
aient services apply --file service-mappings.json --json
aient services apply --file service-mappings.json --apply --json
```

`services apply` is dry-run by default. These commands require the `services:read` and `services:manage` OAuth scopes; existing sandbox access remains valid, while an older profile may need one interactive login before service management.

## Current release boundary

The commands documented in this section are the surface shipped in Aient CLI 0.12.2.

- Environment-bound `status`, `wait`, and `logs` resolve the repeated environment selector through the authenticated profile.
- Exclude-only workspace selection starts from the broad eligible non-Git inventory, keeps Git state authoritative, omits regular macOS AppleDouble `._*` files by default, and applies only caller-supplied exclusions beyond that documented filter.
- Exact `--reset-remote-dir` selection replaces a named remote non-Git directory with an ordinary empty candidate-owned directory without modifying the local source or weakening atomic activation.
- Unselected non-Git paths are absent under explicit repository path ownership, so generated and cache directories remain ordinary removable directories instead of inferred bind-mount roots.
- Repeatable `--preserve-remote-dir` retains only exact declared ordinary remote directories; collision and size checks fail locally before upload, and unsupported servers reject explicit preservation.
- Explicit `--submodules=gitlinks` omits clean exact child checkouts only after recursive local verification and binds the complete parent-index Gitlink boundary into V2 or V3 activation; it does not transfer submodule content.
- Default snapshots preserve raw uninitialized Gitlink index entries without applying constraints that belong only to the explicit Gitlink manifest; explicit mode continues to require UTF-8 portable paths, reject literal backslashes, and enforce the 512-entry bound.
- `sandbox workspace list [--json]` shows the operations other CLI processes are running and removes directories a killed CLI of this version left behind. See [workspace operations](#workspace-operations).
- Idle and timeout cleanup acts only on the exact sandbox revision it evaluated. This protects an accepted concurrent refresh without renewing or extending the operation lease or server-owned hard expiry.
- Customer create and run support the `small`, `medium`, and `large` product-owned compute classes.
- Customer-development create advertises `developmentSizeBindingVersion: v2` and accepts only a complete exact `aientSizeBinding=v2`, `aientSizeClass`, `aientSizeSource=requested|environment-default`, and `aientSizeEnvelope=v1|v2` binding. Invalid combinations fail before the control-plane request; legacy explicit V1 and an old server's unbound default remain rollout-only compatibility paths.
- A conditional one-use `repository-prewarm` path handles an exact-clean same-HEAD workspace at the default repository root. A matching Ready member sends zero committed Git bytes and skips sandbox creation, MinIO reads, and workspace materialization; typed no-ready continues the same immutable capture cold, while an ambiguous claim stops without duplicate work. Dirty overlays, selected repositories, custom roots, explicit names, and other ineligible requests stay on the existing path. Ready-member supply is operator-bounded and not promised for every command.
- Immutable capture overlaps remote preflight. Compact JSON cache phases remain one object per physical line, and `--timing-json` reports `gitCache.outcome=repository_prewarm` with zero client bytes on a hit.
- A stale derived commit-graph that references only pruned unreachable objects does not block capture. Refs and reachable objects remain authoritative, the CLI does not rewrite user Git metadata, and a genuinely missing reachable object still fails before upload.
- Named sandbox creation is replay-safe under bounded ambiguous-transport retries: one public name keeps one idempotency identity, matching fingerprinted settings adopt the accepted sandbox, changed fingerprinted settings conflict, and `sandbox run` never executes in or deletes a sandbox whose returned identity is unproven.
- Organisation selection is bound to one canonical lowercase UUID. The CLI resolves the authenticated display name and canonical organisation UUID for human-readable status and trusted legacy-project migration guidance; the display name is render-only, and every present authenticated identity source must agree before the requested operation.
- Environment-bound sandbox commands carry one authenticated organisation/environment/repository tuple across create, synchronization, files, execution, observation, lease refresh, and deletion. New customer workspace operations record that tuple in `workspace-operation-bundle-v2` and use the exact authority for status and discard instead of weakening to owner-only access; legacy V1 receipts keep their established compatibility behavior.
- The conservative supervised execution timeout ceiling is `23h56m18s`. Larger `sandbox exec` command budgets fail locally before a sandbox request and at server admission before claim creation or provider dispatch with `sandbox_execution_timeout_invalid`; a valid budget can still conflict with the remaining hard lease of an older retained sandbox.
- `aient auth exec --profile NAME -- COMMAND...` gives a trusted same-UID host wrapper one renewable access-only credential while injecting or copying no refresh, profile, operator, or imported portable authority. It is credential minimization, not a local process sandbox; untrusted same-UID descendants require external confinement.
- From a configured project, `aient auth login` installs bounded manager-owned project access by default. Refresh authority remains in the OS credential store; ordinary repository commands discover only the rotating short-lived envelope with no profile/token flags, foreground exporter, or PID tracking.
- Explicit `--submodules=selected` transfers only the named clean exact Gitlink dependency closure; unselected initialized children contribute no bytes and remain empty boundaries.
- Selected submodules may be combined with declared parent-repository extras. The server verifies their exact receipts and capability preflight recognizes the mounted old helper generation.
- `sandbox run` uses supervised execution and allocates one fresh execution per ordinary CLI process. `--json` emits `execution_started` with `executionId` and `outputCursor` before command output; same-process recovery and explicit `--after-cursor` attach replay retained output after the last accepted cursor and never redispatch the command.
- `sandbox run --timing-json` writes one content-free stderr receipt for proven workspace activation through cleanup or retention without changing command output or exit status.
- Automatic cleanup issues exactly one DELETE with the full configured `--timeout`; ambiguous deletion remains an error, and genuine lease-refresh failures still warn and retry.
- `aient services list|paths|classify|apply` manages explicit runtime-service repository mappings. Batch apply is dry-run by default and uses the dedicated `services:read` and `services:manage` OAuth scopes.
- Owner/admin environment-secret writes are encrypted, capability-gated, and write-only from the CLI.
- Synchronization to `/workspace/repo` negotiates V3 immutable-candidate activation when an exact attested server advertises the closed V3 capability; it retains typed V2 on V2 servers and compatible V1 on older servers. V3 selection rejects unknown, duplicate, mixed, or invalid capability evidence before upload and never falls back after selection.
- Workspace synchronization publishes complete, self-contained parent-repository Git history. Shallow, promisor, alternate-backed, grafted, or replace-influenced local sources fail before upload; incompatible sandbox helpers fail before probe or mutation instead of selecting a shallow fallback.
- V2 workspace activation returns success only after the exact activated revision is certified under the same exclusive workspace-operation fence. If the result is lost after commit, the CLI reconciles the same immutable operation within the command and never replays the requested command; a rerun syncs fresh. Separately, genuine cross-writer fence contention can still return typed `workspace_layout_certification_busy`; workspace-backed `sandbox run` retries only that exact pre-dispatch response for up to 10 seconds, honors `Retry-After`, and never replays a user command.

- `aient agent list|status|events|message|respond|cancel|chat` finds or attaches to an existing Agent Thread through the public API. It does not start a new Agent Thread.
- `agent events --follow --json` emits JSONL after durable sequence replay; Ctrl-C detaches ordinary chat without remote cancellation.
- `! COMMAND` in Agent chat runs only in the frozen reported sandbox through supervised execution. Reconnect with `agent execution status|attach|wait|cancel`; no local shell, caller environment, repository inference, or Agent message is added.
- Terminal `agent execution status|wait|cancel` output failure preserves the local selector for a fresh authorized status read of the same execution; successful terminal delivery still retires it. `wait` preserves a nonzero exit even if local retirement fails. Recovery requires surviving server evidence and current authorization, not permanent execution history.
- Supervisor-retained output is cursor-replayable. Cursor acceptance is frame-atomic, so reconnect may repeat the last complete frame but cannot create a gap; retention remains bounded rather than permanent command history.
- `sandbox shell` always opens a new shell. Shell reattachment and shell history are unavailable.
- Selected-file `sandbox sync --live|--live-stream` is experimental. Native V3 `--live-stream` requires normal customer shell permission and holds a shared workspace fence. After `termination UNVERIFIED`, the helper/fence may remain active and block full sync or exclusive files API writes; starting another watcher does not recover it. Neither mode provides conflict protection, deletion/rename propagation, multi-file consistency or reconnect recovery. File ACKs do not establish application readiness, browser HMR or universal subsecond latency.
- `aient sandbox port SANDBOX PORT` publishes a public HTTPS capability URL on a configured native deployment; `aient sandbox port SANDBOX --revoke` removes the binding. Anyone with the URL can access the application. The binding follows the remaining lease and exact incarnation, without another retention owner. Server-side preview routing, certificates, DNS, and exposure policy must be configured; installing the CLI does not establish availability. Agent-owned previews, raw TCP forwarding, and local-resource forwarding are not promised.
- Customer create and run accept `--cpu` and `--memory` requests within the selected size's server-owned limits. Custom requests select the native agent-sandbox provider and bypass preset warm claims; GPU requests remain unsupported. Resource limits and templates remain operator controls.
