# Retained sandbox lifecycle

Retain a sandbox when you want to run several commands against one uploaded workspace. For an environment-bound customer sandbox:

```sh
aient sandbox run \
  --name laptop-offload \
  --keep \
  --environment development \
  --repository example/widget \
  -- true
aient sandbox list --environment development
aient sandbox sync laptop-offload . \
  --environment development \
  --repository example/widget
aient --timeout 15m sandbox exec laptop-offload \
  --environment development \
  --repository example/widget \
  --workdir /workspace/repo -- pnpm test
aient sandbox delete laptop-offload
```

The one-shot command prints the logical sandbox name (the `name` field in JSON). In Aient CLI 0.11.17, that environment-bound sandbox can be reused through selector-bearing `sandbox sync`, `sandbox exec`, and `sandbox execution`, found with environment-scoped `list`, inspected with environment-scoped `status`, `wait`, and `logs`, and removed by its owner with `delete`. Run `sync` to publish changed workspace state. A Modal `sessionId` identifies the physical runtime and is not a command target. `files` and `shell` cannot reopen the sandbox.

## Native sandbox billing

Use Aient CLI 0.11.21 or later to create native customer sandboxes or claim a ready repository sandbox. Older clients cannot create a native allocation through the current billing contract.

| Size | Hourly rate |
| --- | --- |
| Small | €0.15 |
| Medium | €0.60 |
| Large | €1.20 |

We bill native sandbox occupancy in whole seconds and round the final session amount once to the nearest cent. Existing sessions keep their original terms.

An initial €5 reservation counts against your spending limits. It is not a session cap: usage can exceed €5 while your user and organisation limits allow it, within the sandbox's finite lease. Delete a retained sandbox when you finish using it.

If billing denies creation, the CLI reports that no sandbox was created. If the creation result is uncertain, use the exact sandbox name and recovery command printed by the CLI. A transport retry reuses the original allocation and reservation.

## `aient sandbox list`

List sandboxes visible to the selected profile:

```sh
aient sandbox list
aient sandbox list --environment development
aient sandbox list --json
```

`--environment` applies customer environment authorisation before listing. `--json` is useful for scripts.

## `aient sandbox create`

Create a retained sandbox without running a command:

```sh
aient sandbox create --name laptop-offload --lease-seconds 21600
```

| Flag | Meaning |
| --- | --- |
| `--name NAME` | Requested sandbox name. |
| `--lease-seconds N` | Requested lease. Default `7200`. |
| `--metadata KEY=VALUE` | Non-secret control-plane metadata entry. Repeatable. |
| `--json` | Emit structured output. |
| `--ssh-known-hosts auto\|none` | Bootstrap repository-scoped public SSH host trust for the sandbox user. Default `auto`; use `none` to opt out. |

Metadata must never contain credentials or sensitive values. It cannot override server-owned organisation, actor, environment, or repository identity.

The default Git transport bootstrap uses only hosts selected by the current repository's `origin`, `upstream`, and root `.gitmodules`. It merges matching public host records into the guest and, for GitHub, configures the sandbox user to use scoped HTTPS repository authority for SSH-form URLs. It does not copy private keys, SSH configuration, agents, sockets, or credentials. Installation restrictions produce a warning without turning successful sandbox creation into a failure.

For customer work that needs an environment's authorised development capabilities, prefer `sandbox run --environment ... --keep` or supply `--environment` on later `exec` and execution-observation operations.

## `aient sandbox status`

Show the current state of a sandbox:

```sh
aient sandbox status laptop-offload
aient sandbox status laptop-offload --json
aient sandbox status laptop-offload --environment development
```

Repeat the original `--environment` selector for an environment-bound customer sandbox.

## `aient sandbox wait`

Wait until a sandbox becomes ready:

```sh
aient --timeout 10m sandbox wait laptop-offload
aient --timeout 10m sandbox wait laptop-offload --environment development
```

| Flag | Meaning |
| --- | --- |
| `--poll-interval DURATION` | Status polling interval. Default `500ms`. |
| `--json` | Emit structured output. |

The global `--timeout` limits the wait.

Repeat the original `--environment` selector for an environment-bound customer sandbox.

## `aient sandbox exec`

Run a supervised command in an existing sandbox:

```sh
aient --timeout 15m sandbox exec laptop-offload \
  --environment development \
  --repository example/widget \
  --workdir /workspace/repo -- pnpm test
```

The CLI prints a stable execution ID to stderr before dispatch:

```text
Execution: 12345678-1234-4123-8123-123456789abc
```

Keep the sandbox name and execution ID if you may need to inspect or reconnect to the live execution.

| Flag | Meaning |
| --- | --- |
| `--workspace PATH` | Synchronise a local checkout before running the command. |
| `--workdir ABSOLUTE_PATH` | Working directory. Default `/workspace`. |
| `--env KEY=VALUE` | Non-secret environment value. Repeatable. |
| `--environment SLUG_OR_ID` | Authorise use of customer development capabilities. |
| `--repository OWNER/NAME` | Select verified repository authority for provider-capable execution. |
| `--shell COMMAND` | Explicit shell command. |
| `--stdin` | Read an explicit shell command from standard input. |

Exact argv, `--shell`, and `--stdin` are mutually exclusive command forms. Repository authority requires `--environment`.

`sandbox exec` performs bounded same-execution transport recovery. It never replays an execution that may already have started.

## `aient sandbox docker bootstrap`

Start a tmpfs-backed Docker daemon in a retained sandbox when a workflow needs Docker across more than one supervised command:

```sh
aient --timeout 30m sandbox docker bootstrap laptop-offload \
  --environment development \
  --repository example/widget
```

The daemon runs as a detached supervised execution from `/workspace/repo`. On compatible servers, it keeps live workspace consistency, so the daemon remains usable while a workspace sync publishes a new revision. `--timeout` bounds the daemon lifetime; the sandbox's retention policy still applies.

Use `--reset` only to replace an existing daemon. It erases Docker and containerd data before preparation. If the CLI finds a ready daemon without a known live-consistency contract, it reports `docker ready` and tells you to rerun with `--reset` or recreate the sandbox before relying on sync.

An incompatible server rejects bootstrap before changing Docker state. Keep the printed execution ID if bootstrap does not complete so you can inspect its terminal state instead of starting another daemon.

## `aient sandbox shell`

Open a new interactive PTY shell in a sandbox without an environment binding:

```sh
aient sandbox shell laptop-offload
```

Every invocation opens a new shell. Shell reattachment, history replay, and capability-bearing environment or repository flags are not available, so `shell` cannot address an environment-bound customer sandbox. Use `sandbox exec --environment ...` for authorised non-interactive operations.

## `aient sandbox logs`

Read a bounded recent log snapshot from a sandbox:

```sh
aient sandbox logs laptop-offload
aient sandbox logs laptop-offload --tail-lines 500
aient sandbox logs laptop-offload --json
aient sandbox logs laptop-offload --environment development
```

This is a sandbox runtime log snapshot, not stored command stdout/stderr history.

Repeat the original `--environment` selector for an environment-bound customer sandbox.

## `aient sandbox delete`

Delete a sandbox:

```sh
aient sandbox delete laptop-offload
```

Delete retained sandboxes when you are finished. A sandbox lease is not a substitute for explicit cleanup.
